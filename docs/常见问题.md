# 需求方常见关切

按客户实际会问的顺序排。答案只写已经落地的东西，做不到的直接说做不到。

---

### 1. 什么类型的工厂最贴合？

按**重量 × 单价**计价的那一类：五金、注塑、包装材料、纺织面料、铝材、化工分装、农产品初加工等。
订单行的字段是「品名 + 规格 + 颜色 + 重量 + 单价」。

如果你的行业按**件数 / 米数 / 面积**计价，本系统当前形态不合适——那不是加一个字段的事，计价口径会同时改到明细模型、金额重算规则、看板统计和四个入口共用的校验定义。**先谈再动手。**

### 2. 数据在谁手上？

私有化部署：程序和数据都在你方服务器（自建或你名下的云主机），MySQL 实例归你方，备份策略由你方掌握。

需要说明的一点：**当前版本登录用账号 + 密码，不依赖微信授权登录。**
好处是不需要额外申请微信开放平台的接口权限、也不会被平台的审核节奏绑住；代价是每个员工记一个口令。要改成微信一键登录属于新增范围，需单独评估。

### 3. 员工离职，他录的单归谁？

归属永远按**创建人**算，代录人只作业务留痕，两者分开记录。所以「业务员走了，他名下的单找不着主」这一类争议在数据层面是可追溯的。
停用账号在后台操作，账号停用后其历史单据仍留在原归属范围内。

### 4. 客户、产品、部门这些资料要找你改吗？

不用。后台有独立的资料维护页：客户、产品、部门树、员工账号（建号 / 停用 / 重置密码 / 分配角色）、数据字典、系统参数。
**资料与配置的唯一写入口就是后台页面本身**，小程序端只读——这样不会出现「后台改了、小程序还是旧数据」这种两个数对不上的情况。

### 5. 权限位能自己调吗？

能，在后台的角色页直接勾选。
更关键的是：**小程序页面的按钮和底部导航槽位全部按服务端下发的权限渲染，不看角色名。** 所以调整「主管能不能作废」这类口径，改完即生效，**不需要重新发小程序版本**——小程序发版要过审，是这类项目最容易被低估的隐性成本。

### 6. 为什么状态只有三个？没有「部分发货」？

原始原型里有六个状态，且互相矛盾（同一个状态在不同人嘴里有两个名字）。落地时收敛为三态：**未完成 / 已完成 / 已作废**，`未完成 → 已完成` 是唯一的迁移。
发货是**整单发货**，不做部分发货——部分发货需要引入发货批次模型，那是另一套东西。

### 7. 已经发货的单发现录错了怎么办？

**改不了，也删不了**——对已完成订单发起修改或删除会被拒绝。作废也只允许对未完成的单做。
当前版本没有「更正单」这一形态。已落地的做法是：新建一张正确的单，用备注说明与原单的关系。
如果贵方需要正式的更正流程（原单冲正 + 新单关联 + 审批），这是需要单独谈的变更。

### 8. 删掉的单能恢复吗？会不会偷偷丢数据？

删除是**软删 + 留痕**，后台管理员可恢复，每一次改单、作废、发货都留一条操作记录，后台有只读的留痕查询页。

### 9. 报表有什么？

- 后台看板 4 个图表：订单趋势、订单异常、发货时效、人员录单表现。
- 小程序工作台：本月订单总数与按日张数。
- 后台订单列表支持按条件筛选后导出。

统计口径只算一次（同一份 service 同时供后台看板与小程序接口），不会出现两个入口给出两个数。

### 10. 车间网络差，能离线录单吗？

**不能。** 全部操作走接口，要求联网。离线暂存与补传不在当前版本范围内。

### 11. 需要什么样的服务器？

PHP 8.3 + MySQL 8.0 + Nginx 的常规 LAMP/LNMP 环境即可，与后台同应用部署（不需要单独起前端构建服务）。

具体 CPU/内存规格**要按贵方日均单量与并发录单人数实测后给**，这里不给未经压测的数字。

### 12. 和现有 ERP / 进销存怎么共存？

本系统只管到「发货」为止，**不写 ERP、不做库存扣减、不做财务**。
常见分工是：销售与发货在这套系统里跑，之后由 ERP 承接库存与账务。若要打通（比如订单同步给 ERP），需要单独评估双方接口。

### 13. 报价怎么算？

跟三个变量有关：是否需要字段/流程定制、部署环境（有无云主机和运维）、是否需要与现有系统对接。
**带着「行业 + 日均单量 + 几个人录单 + 现在用什么记」来谈**，可以直接给出范围。公开报价对双方都没有意义，所以不写在仓库里。

### 14. 想看真实运行的界面，而不只是设计稿？

可以预约一次远程演示。演示环境的数据为示意数据，不含任何真实客户资料。
