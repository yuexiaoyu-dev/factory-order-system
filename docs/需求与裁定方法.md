# 我们是怎么把「一张原型图」变成「能开工的规格」的

这份文档写给两类人：一是想知道我们做项目的方式、据此判断要不要合作的客户；二是同行。

---

## 1. 原型只画了正常路径，缺口才是工作量

一份产品原型通常长这样：每个角色操作成功之后屏幕是什么样子。它**不会**画：

- 没有权限的人点进来是什么样；
- 接口挂了、这个月一张单都没有、加载还没完成，分别长什么样；
- 一个人同时属于两个角色怎么办；
- 后台管理端（十有八九根本没画）；
- 同一条规则在两个入口上说法不一致时，听谁的。

而真正让项目返工的，全在这五条里。

所以我们的第一道工序不是画屏，是**把每一条口径标上来源**。全文强制四类标注：

| 标注 | 含义 | 谁来定 |
|---|---|---|
| `原型实证` | 原型里确实画了/写了 | 不用讨论，照做 |
| `设计推导` | 原型没有，但不补两端就跑不通 | 需评审确认 |
| `口径冲突` | 原型自相矛盾 | 我们给取舍建议，你签字 |
| `待确认` | 只能业务方开口，技术侧无法替你决定 | **必须等人** |

这套标注的价值不在文档好看，在于**每一条分歧都有归属**：哪些是我们替你做的决定、哪些是我们不能替你做的决定，事后翻记录能对上。项目做到一半才发现「原来你们理解的和我想的不一样」，绝大多数就出在该标 `待确认` 的地方被顺手实现了。

## 2. 三个真实的收敛例子

**状态机从六个收成三个。**
原型里同时出现六种状态叫法，其中两个词在不同页面指同一件事，另有两个词在不同页面指不同的事。如果照原样实现，会出现「已发货」在业务员嘴里是完成、在仓库嘴里是待出库。
落地为 `未完成 / 已完成 / 已作废` 三态，`未完成 → 已完成` 是唯一迁移，已完成之后一律拒改拒删。**并且这条要在接口层真的拒绝**——前端把按钮藏掉不算锁，任何人绕过页面直接调接口仍然能改。

**订单行要不要「数量」字段。**
原型明细里有数量，但计价口径写的是重量 × 单价，两个字段同时存在就必然出现「数量 2、重量 42 公斤，到底按哪个算钱」。裁定：取消数量字段，金额只由重量 × 单价决定，**而且合计由服务端重算，客户端传来的金额不作数。**

**「轻端重后台」的职责切分。**
原型把录入、查看、发货、删除、改密全塞在小程序一端。落地时把资料维护、组织与权限、恢复与留痕、导出、报表全部收进 Web 后台，小程序只留现场要做的事。
判断依据是一句话：**手机是拿来在现场把事办完的，不是拿来配字典的。**

## 3. 权限按「权限点」算，不按角色名写死

7 个内置角色、10 个权限点、3 档数据范围（本人 / 本部门及下属 / 全部）。
角色是权限点的组合，代码里不出现 `if (role == '主管')` 这种东西。带来的直接收益：

- 客户说「主管不能作废」时，改一个勾选，不改代码；
- 小程序的按钮和底部导航槽位**全部由服务端下发的权限与状态算出来**，所以改口径不用发版，也就绕开了审核等待；
- 数据范围在服务端注入查询，不是把全量拉到前端再过滤——后者意味着抓包就能看到别人的单。

## 4. 按角色逐屏实测，而不是对着表格检查

对着权限矩阵看，看不出「这个人打开应用到底能走到哪一屏、那一屏上有没有按钮」。
所以我们用 7 个真实账号各登录一次，逐个记录：数据范围、列表里有几张单、卡片上有没有快钮、详情页底部动作条下发了什么、对已完成订单发起改/删拿到的返回码。跑完把结论固化成断言。

这一轮跑出来两个只对「使用者」可见、对「阅读者」完全隐形的缺陷：

1. 服务端下发给小程序一个「导出」动作，而小程序七个页面里没有任何导出入口——导出只在 Web 后台。用户点了却没地方用。
2. 三个零动作角色的屏底挂着一条 38px 高的**空白操作条**。它不是 bug 报错，只是一条空白，肉眼在开发阶段极容易忽略，但它让每一屏都显得「少了点什么」。

顺带还量到一处接口行为：已发货的单，**有权限的人**改它拿 409，**没权限的人**改它拿 403——状态不允许与身份不允许，是两个不同的答案，前端提示文案要分开写。

## 5. 契约以实现为准回头改文档

实现过程中发现原本写的接口形态不合理时，我们改文档，不改代码去迁就旧文档。
理由：文档一旦和实现长期不一致，下一轮评估、二次开发、验收，三方各自读到的都是不同的事实。这一份规格里的每一条修订都带日期和「上一版是怎么说的」，包括我们自己写错的那几处——**不静默改写，就地更正并保留原记录**。

## 6. 不承诺没有测量过的东西

收益类指标（录单省多少时间、错单率降多少）需要客户先给基线数，我们**不替客户估**。
能举证的只有工程质量那一半：1,030 条断言、四个入口共用同一套校验定义、取数失败不伪装成空结果、幂等键防重复发货。这两半混着卖，最后一定变成一句「显著提升效率」的空话。
